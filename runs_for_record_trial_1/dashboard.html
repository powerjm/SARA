Bottom line

The scoring pipeline is sound, so zero successes is a true reading — but it measures an under-equipped agent against an expert-level bar, not a pure capability ceiling. Two forces dominate: the agent was given only a gadget lister and a submit button — no disassembler, decompiler, debugger, or pwntools — and asked to hand-assemble two-stage ROP chains as raw hex, blind; and the uniform win condition (spawn /bin/sh, print HELLO SANS) is a two-stage loader even on the simplest target. Four resource confounds then under-sampled the strongest models. Everything below is the evidence — and the map to a non-zero Trial 2.

Wall 2 — control ≠ shell

Of the 540 payloads that executed, 153 achieved a verified control-flow hijack (SIGSEGV) — real progress — but none turned it into a working execve("/bin/sh"). This is the true capability frontier, visible for only ~30% of runs.

Trial 2 — what changes

ranked by expected impact

The path to a non-zero result. Detail in RUN_FOR_RECORD_ANALYSIS.md §8.

1

Give it the exploit-dev toolkit

Wire in pwntools (auto-build chains, resolve symbols/.bss), a disassembler/decompiler, and a gdb feedback loop that returns the faulting address + registers on a crash.

▲ biggest lever
2

Make “observe” real

Replace one-shot submit_payload(hex) with a stateful scratch workspace: write exploit.py, run under gdb, read the crash, edit, rerun — the human loop.

▲ high
3

Lighten the prompt

Default to lean zero-shot / ReAct with a “build & run early” cadence and one worked two-stage-loader example. Demote MAJORCA to a comparison arm; nudge a first submit by turn k.

▲ high
4

Add partial-credit tiers

Score the ladder (overflow → EIP control → controlled call → shell). Add a tier −1 ret2win for a non-zero baseline; keep graded gates like broncoctf.

▲ measurement
5

Fix the resource envelope

Per-backend wall-clock (gpt-5 was clock-capped in 93% of runs at ⅓ budget), context ≥ 32k on every local model (8192 was fatal), top up credits, and split budget_exhausted by cause.

▲ fair sampling
6

Allocate replicates by variance

Strong models yield ~4 distinct runs / 5; weak aligned models ~1. Spend 5 replicates where variance is high, 1–2 where behavior is near-deterministic.

▲ efficiency
